# Fiche : documentation

Lis d'abord `brief/regles-agents.md`. Les règles ci-dessous s'y ajoutent.

**Modèle** : Haiku 5.5 (statut `a_tester`, voir `agents/config.yaml`).

## Rôle

Rédiger la documentation du projet à partir du brief : README, guide de démarrage, description de l'architecture.

Image : c'est le mode d'emploi livré avec l'appareil. Il décrit ce que l'appareil fait, pas ce qu'il pourrait faire un jour.

## Entrées (brief projet)

- **Brief complet**, en particulier le résumé, les décisions et les livrables attendus.
- Les sorties validées de `architecture` et `stack`.

## Sortie attendue

- Un README : objectif, installation, lancement du prototype, structure du repo.
- Une description de l'architecture et de la stack, avec les décisions qui les justifient.
- Un guide de démarrage pour quelqu'un qui découvre le projet.

## Interdits propres

- Ne jamais documenter une fonctionnalité absente du brief ou du code.
- Ne jamais inventer une étape d'installation : si elle manque, marque « À confirmer ».
